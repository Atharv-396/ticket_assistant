## Important Technical Decisions

### Multi-turn via messages table
Storing every turn in `messages` with role=user/assistant means the full
conversation is always available. On every Gemini call the complete history
is injected into the prompt so the AI has full context.

### RAG re-runs on every follow-up
The retrieval query is rebuilt from the initial message + latest user turns.
This means follow-up messages like "order value is ₹3,500" change which policy
chunks are retrieved, giving Gemini the most relevant context for each turn.

### IN_PROGRESS / FINAL status on decisions
Every Gemini response carries a status. The frontend and API use this to:
- Show a question form (IN_PROGRESS)
- Show a final recommendation (FINAL)
- Close the ticket (FINAL)

### Pydantic validates all Gemini output
`AIDecision` validates action, status (must be IN_PROGRESS or FINAL),
confidence (0.0–1.0), and coerces sources/required_information to lists.
No raw LLM string is ever stored in the database.

### StaticPool for tests
SQLite `:memory:` creates a new empty database per connection. Using
`StaticPool` forces all connections to share one DBAPI connection, so
`create_all` tables are visible to every session in the test.

## Bugs Found and Fixed

1. **SQLite per-connection isolation in tests** — Fixed with `StaticPool`.
2. **Gemini markdown fences** — Gemini wraps JSON in ` ```json ``` `.
   Fixed with regex strip in `_parse_and_validate()`.
3. **bcrypt/passlib version warning** — passlib reads `bcrypt.__about__`
   which was removed in bcrypt 4.x. Fixed with `warnings.filterwarnings`.
4. **Embedding model unavailable** — `text-embedding-004` not accessible
   on this API key. Switched to `models/gemini-embedding-001`.
5. **G: drive read-only** — BUILTIN\Users had only ReadAndExecute on
   `G:\mansor_lab`. Fixed by granting FullControl via elevated PowerShell.
